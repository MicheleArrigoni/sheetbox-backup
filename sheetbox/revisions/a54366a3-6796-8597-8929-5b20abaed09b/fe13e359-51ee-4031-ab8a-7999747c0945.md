## 1. Setup, devices, and reproducibility

Install the appropriate build with the [official selector](https://pytorch.org/get-started/locally/).

```python
import random
import numpy as np
import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader, random_split

random.seed(42)
np.random.seed(42)
torch.manual_seed(42)
device = torch.device('cuda' if torch.cuda.is_available()
                      else 'mps' if torch.backends.mps.is_available()
                      else 'cpu')
print(torch.__version__, device)
```

Move the model before constructing its optimizer. Move inputs and targets to a compatible device. Seeds do not guarantee identical results across releases, hardware, or nondeterministic kernels. `torch.use_deterministic_algorithms(True)` can help but may reduce speed or raise on unsupported operations. Record environment and data-split seeds. [Reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html).

## 2. Creation, dtype, and inspection

```python
t = torch.tensor([[1., 2., 3.], [4., 5., 6.]], dtype=torch.float32)
z = torch.zeros((2, 3), device=device)
ones = torch.ones_like(t)
noise = torch.randn(2, 3)
indices = torch.arange(6)            # int64
grid = torch.linspace(0, 1, 5)
print(t.shape, t.ndim, t.numel(), t.dtype, t.device, t.requires_grad)
converted = t.to(device=device, dtype=torch.float32)
assert torch.tensor(3.).item() == 3.0
```

`torch.tensor(data)` copies. `torch.as_tensor(data)` can reuse memory; `torch.from_numpy(array)` shares supported NumPy CPU storage. Floating models commonly use float32; class-index targets use `torch.long`; masks use `torch.bool`. `.to(...)` may return the original tensor when no conversion is needed: assign its result. `.item()` requires one element and can synchronize an accelerator. [Tensor API](https://docs.pytorch.org/docs/stable/tensors.html).

## 3. Indexing, shapes, and memory

```python
assert t[:, 1].shape == (2,)
assert t[:, 1:2].shape == (2, 1)
selected = t[t > 3]
matrix = torch.arange(24).reshape(2, 3, 4)
reordered = matrix.permute(0, 2, 1)   # (2, 4, 3)
swapped = matrix.transpose(-1, -2)    # last two dimensions
flat = reordered.reshape(2, -1)      # may copy
column = torch.arange(3).unsqueeze(1) # (3, 1)
assert column.squeeze(1).shape == (3,)
joined = torch.cat([t, t], dim=0)     # (4, 3): existing dimension
stacked = torch.stack([t, t], dim=0)  # (2, 2, 3): new dimension
independent = t.clone()
```

Basic slicing generally shares storage; advanced indexing reads produce copies. `view` requires compatible strides; `reshape` returns a view or copy. Use `.contiguous()` when an operation requires contiguous layout. `squeeze()` without a dimension can accidentally remove a size-one batch dimension. `.T` is best reserved for 2D matrices; use `transpose(-1,-2)` for batched matrices. Avoid in-place changes to values needed by autograd.

## 4. Arithmetic, reductions, and broadcasting

```python
elementwise = t * t
product = t @ t.T                    # (2, 2)
per_column = t.mean(dim=0)            # (3,)
per_row = t.sum(dim=1, keepdim=True)  # (2, 1)
row_max, row_indices = t.max(dim=1)
row_max_only = torch.amax(t, dim=1)
population_std = t.std(dim=0, correction=0)
sample_std = t.std(dim=0, correction=1)
bounded = t.clamp(min=2, max=5)
choice = torch.where(t > 3, t, torch.zeros_like(t))
assert torch.allclose(t, t.clone(), rtol=1e-5, atol=1e-8)
assert torch.isfinite(t).all().item()
```

Broadcasting compares dimensions from the right: they must match or one must be 1. `(N,1) + (N,)` produces `(N,N)`, often a silent bug. Integer tensors need conversion for `mean`. PyTorch `std` defaults to correction 1; NumPy `std` defaults to `ddof=0`. Reduction parameters are generally `dim`/`keepdim` in PyTorch, `axis`/`keepdims` in NumPy.

## 5. Autograd

```python
w = torch.tensor([2., -1.], requires_grad=True)
loss = w.square().sum()
loss.backward()
assert torch.equal(w.grad, torch.tensor([4., -2.]))
w.grad = None
detached = w.detach()                # shares storage; no gradient history
snapshot = w.detach().clone()        # independent storage
```

`backward()` accumulates gradients into leaf tensors' `.grad`. Non-leaf gradients are not retained by default; use `.retain_grad()` if needed. A nonscalar output needs an upstream gradient or a reduction. The graph is normally freed after backward; rerun the forward pass for a new step. `.item()`, NumPy conversion, and `detach()` break the differentiable path. `clone()` alone preserves the path.

`torch.no_grad()` disables recording within a block. `torch.inference_mode()` removes additional bookkeeping, but its tensors have restrictions when reused in grad-tracked work. `model.eval()` controls layer behavior and does not disable autograd. [Autograd mechanics](https://docs.pytorch.org/docs/stable/notes/autograd.html).

## 6. Modules and layer shapes

```python
class Classifier(nn.Module):
    def __init__(self, features=12, classes=3):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(features, 32), nn.ReLU(), nn.Dropout(0.1),
            nn.Linear(32, classes),
        )

    def forward(self, inputs):
        return self.layers(inputs)

model = Classifier().to(device)
parameter_count = sum(p.numel() for p in model.parameters() if p.requires_grad)
```

Call `model(x)` so hooks run. Store child layers in module attributes, `ModuleList`, or `ModuleDict`; plain Python lists do not register their contents. Use `register_buffer` for nontrainable tensor state that should move with the model and appear in its state dictionary.

| Layer | Typical input → output |
| --- | --- |
| `Linear(D,H)` | `(...,D)` → `(...,H)` |
| `Conv2d(Cin,Cout,k)` | `(N,Cin,H,W)` → `(N,Cout,Hout,Wout)` |
| `MaxPool2d(k)` | Reduces spatial dimensions |
| `Flatten(start_dim=1)` | Preserves batch; flattens the remaining dimensions |
| `Embedding(V,D)` | Integer indices `(...)` → `(...,D)` |
| `LayerNorm(D)` | Normalizes trailing dimensions of size D |
| `BatchNorm2d(C)` | Channel statistics; training/eval behavior differs |
| `LSTM(D,H,batch_first=True)` | `(N,L,D)` → output `(N,L,directions*H)` plus states |

For convolution with default floor behavior: `Hout = floor((H + 2*p - d*(k-1) - 1)/s + 1)`; similarly for width. Check padding/stride/dilation. [Neural network reference](https://docs.pytorch.org/docs/stable/nn.html).

## 7. Loss contracts

| Task / loss | Model output | Target |
| --- | --- | --- |
| Multiclass `CrossEntropyLoss` | Raw logits `(N,C)` | Class indices `(N,)`, long, in `[0,C)` |
| Segmentation `CrossEntropyLoss` | Logits `(N,C,H,W)` | Indices `(N,H,W)`, long |
| Binary / multilabel `BCEWithLogitsLoss` | Raw logits `(N,1)` or `(N,C)` | Same shape, floating values in `[0,1]` |
| Regression `MSELoss` / `L1Loss` | Predictions `(N,D)` | Matching shape and floating dtype |
| `NLLLoss` | Log probabilities `(N,C)` | Class indices `(N,)`, long |

Do not apply softmax before cross entropy, or sigmoid before BCEWithLogitsLoss. For inference use softmax for mutually exclusive classes, sigmoid for independent binary labels. Cross entropy also accepts probability targets under a different contract: floating values with exactly the same shape as logits and valid per-sample class distributions. The table uses class indices. Shape mismatches in regression can broadcast silently.

## 8. DataLoader and complete train/validation loop

This self-contained example after sections 1 and 6 uses synthetic data and a fixed split. No dataset download. Validation estimates performance on held-out samples from this synthetic process.

```python
features = torch.randn(360, 12)
teacher = torch.tensor([[2., -1., 0.], [0., 2., -1.], [-1., 0., 2.]])
labels = (features[:, :3] @ teacher).argmax(dim=1)
dataset = TensorDataset(features, labels)
train_ds, val_ds = random_split(dataset, [288, 72],
                               generator=torch.Generator().manual_seed(7))
train_loader = DataLoader(train_ds, batch_size=32, shuffle=True, num_workers=0)
val_loader = DataLoader(val_ds, batch_size=64, shuffle=False, num_workers=0)
model = Classifier().to(device)
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
history = []

for epoch in range(5):
    model.train()
    train_sum = 0.0
    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)
        optimizer.zero_grad(set_to_none=True)
        logits = model(xb)
        loss = loss_fn(logits, yb)
        loss.backward()
        # Optional clipping, after backward and before step:
        # nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()
        train_sum += loss.item() * xb.size(0)

    model.eval()
    val_sum, correct, count = 0.0, 0, 0
    with torch.inference_mode():
        for xb, yb in val_loader:
            xb, yb = xb.to(device), yb.to(device)
            logits = model(xb)
            val_sum += loss_fn(logits, yb).item() * xb.size(0)
            correct += (logits.argmax(dim=1) == yb).sum().item()
            count += xb.size(0)
    metrics = {'train_loss': train_sum / len(train_ds),
               'val_loss': val_sum / count, 'val_accuracy': correct / count}
    history.append(metrics)
    print(epoch + 1, metrics)
```

The sample-weighted loss average is valid here for an unweighted mean loss with one target per sample. Weighted/ignored labels require an appropriate denominator. Fit preprocessing only on training data; split by subject or time when independent random samples would leak information. Keep test data separate from model selection.

`Dataset` normally implements `__len__` and `__getitem__`; `collate_fn` controls batching variable-length samples. `num_workers=0` is portable; on Windows, use a main guard when starting worker processes. For CUDA transfers, consider `pin_memory=True` and `.to(device, non_blocking=True)` after measuring. [Data loading](https://docs.pytorch.org/docs/stable/data.html), [optimization](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html).

## 9. Inference, freezing, and optimizer rules

```python
model.eval()
with torch.inference_mode():
    logits = model(features[:8].to(device))
    probabilities = logits.softmax(dim=-1)
    predictions = logits.argmax(dim=-1)
print(predictions.cpu().tolist())
```

Freeze selected parameters with `parameter.requires_grad_(False)` and rebuild/filter optimizer parameter groups when appropriate. Freezing parameters does not stop BatchNorm running-stat updates in training mode. For schedulers, follow their contract: e.g. `StepLR.step()` after an epoch's optimizer steps; `ReduceLROnPlateau.step(val_loss)` after validation. Do not keep graph-connected losses in a history list; save scalar values or detached tensors.

## 10. Save weights and resume training

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / 'checkpoint.pt'
    torch.save({'model': model.state_dict(),
                'optimizer': optimizer.state_dict(), 'epoch': epoch}, path)
    restored = Classifier().to(device)
    restored_optimizer = torch.optim.AdamW(restored.parameters(), lr=1e-3)
    checkpoint = torch.load(path, map_location=device, weights_only=True)
    restored.load_state_dict(checkpoint['model'])
    restored_optimizer.load_state_dict(checkpoint['optimizer'])
    next_epoch = checkpoint['epoch'] + 1
    restored.eval()                    # or train() to resume
```

Recreate the architecture before loading. Exact training continuation may also need scheduler/scaler state, RNG state, sampler position, and preprocessing configuration. `model.state_dict()` is not an independent in-memory best-model snapshot: save immediately or use `copy.deepcopy`. Load trusted artifacts; `weights_only=True` narrows deserialization but is not a universal safety guarantee. [Serialization](https://docs.pytorch.org/docs/stable/notes/serialization.html).

## 11. Mixed precision and performance

Optional CUDA float16 training step, using the model, optimizer, and loss from section 8:

```python
if device.type == 'cuda':
    model.train()
    scaler = torch.amp.GradScaler('cuda')  # create once, outside the real loop
    xb, yb = next(iter(train_loader))
    xb, yb = xb.to(device), yb.to(device)
    optimizer.zero_grad(set_to_none=True)
    with torch.autocast(device_type='cuda', dtype=torch.float16):
        loss = loss_fn(model(xb), yb)
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    scaler.step(optimizer)
    scaler.update()
```

Autocast belongs around forward and loss; backward is outside. Unscale before gradient clipping. CPU bfloat16 autocast follows a different device/dtype choice and generally does not need a float16 scaler. Benchmark `torch.compile(model)` on supported environments; compilation has startup costs. Use `torch.profiler` or `torch.utils.benchmark`; asynchronous CUDA timing needs synchronization or CUDA events. [AMP](https://docs.pytorch.org/docs/stable/amp.html).

## 12. NumPy bridge and troubleshooting

```python
array = np.arange(6, dtype=np.float32)
shared = torch.from_numpy(array)
shared[0] = 99
assert array[0] == 99
copy = torch.tensor(array)
back = shared.detach().cpu().numpy()  # may share CPU tensor storage
independent_array = back.copy()
```

The usual NumPy bridge requires supported dtype/layout. NumPy does not represent every PyTorch dtype (e.g. convert bfloat16 to float32 first). Use `.resolve_conj().resolve_neg()` if those tensor flags prevent conversion. Negative-stride NumPy views need a copy before `from_numpy`.

| Problem | Check |
| --- | --- |
| Matmul/Linear mismatch | Last feature dimension; flatten spatial axes deliberately |
| Device/dtype error | Model parameters, inputs, targets, newly created tensors |
| Loss stays flat | Learning rate, labels, train mode, gradients, preprocessing |
| Missing gradients | `detach`, `no_grad`, `.item`, leaf status, frozen parameters |
| GPU memory grows | Retained graphs, tensors in logs, batch size |
| In-place autograd error | Replace mutation with an out-of-place expression |
| NaN/Inf | Input finiteness, loss scale, learning rate, gradient norms |
| Good train / poor validation | Leakage, overfitting, split, preprocessing, eval mode |
| Default std differs from NumPy | `correction=0` versus NumPy's `ddof=0` |

`torch.cuda.empty_cache()` releases unused cached blocks; it does not free live tensors or fix retained graphs. Advanced references: [distributed training](https://docs.pytorch.org/docs/stable/distributed.html), [profiler](https://docs.pytorch.org/docs/stable/profiler.html), [torch.compile](https://docs.pytorch.org/docs/stable/generated/torch.compile.html).

Verification: all 11 Python blocks executed with Python 3.14.8, NumPy 2.5.3, and PyTorch 2.14.0+rocm10.1.0 on a CUDA-compatible ROCm device. Training, validation, checkpoint restoration, and the mixed-precision branch passed. Other devices, distributed training, and compilation were not exercised.
