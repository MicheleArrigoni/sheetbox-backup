# CUDA Programming — cheatsheet C++

Riferimento pratico per kernel CUDA C++ e Runtime API. Esempi con C++17 e API consolidate; disponibilità di GPU, architetture e compilatore host dipende dal Toolkit installato. Il programma completo sotto è un esempio didattico, non compilato né eseguito durante la preparazione.

## 1. Modello di esecuzione

| Termine | Significato |
|---|---|
| Host / device | CPU / GPU |
| Kernel | Funzione GPU dichiarata `__global__`, normalmente lanciata dall'host |
| Grid → block → thread | Gerarchia di un lancio |
| Warp | Gruppo di 32 thread; divergenza nei rami può ridurre l'efficienza |
| `__device__` | Funzione eseguita sul device |
| `__host__ __device__` | Compilazione della funzione per entrambi |

`kernel<<<grid, block, sharedBytes, stream>>>(args...)`: gli ultimi due parametri sono opzionali. Il lancio è asincrono rispetto all'host. Non assumere un ordine di esecuzione fra blocchi.

Fonte: [Introduzione a CUDA C++](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/intro-to-cuda-cpp.html).

## 2. Indici e configurazione

```cpp
// 1D: indice globale e passo di una grid-stride loop
size_t i = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
size_t stride = size_t(blockDim.x) * gridDim.x;
for (; i < n; i += stride) {
    // elabora l'elemento i
}

// 2D: matrice row-major, colonne contigue
size_t x = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
size_t y = size_t(blockIdx.y) * blockDim.y + threadIdx.y;
if (x < width && y < height) {
    size_t offset = y * width + x;
    // elabora offset
}
```

Parti da 128 o 256 thread per blocco, multipli di 32, poi misura. Per 2D una base possibile è `dim3 block(32, 8)`. Rispetta `maxThreadsPerBlock`, `maxThreadsDim`, `maxGridSize` e le risorse del kernel: consulta `cudaGetDeviceProperties`. Non lanciare una griglia vuota quando `n == 0`.

## 3. Esempio completo: somma vettoriale

Salva come `vecadd.cu`. Include gestione errori, trasferimenti, controllo del risultato e rilascio della memoria nel percorso normale.

```cpp
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cstddef>
#include <cmath>
#include <vector>

#define CUDA_CHECK(expr) do {                                    \
    cudaError_t err_ = (expr);                                   \
    if (err_ != cudaSuccess) {                                   \
        std::fprintf(stderr, "%s:%d: %s\n", __FILE__, __LINE__,   \
                     cudaGetErrorString(err_));                  \
        std::exit(EXIT_FAILURE);                                \
    }                                                           \
} while (0)

__global__ void vecadd(const float* a, const float* b,
                       float* c, size_t n) {
    const size_t stride = size_t(blockDim.x) * gridDim.x;
    for (size_t i = size_t(blockIdx.x) * blockDim.x + threadIdx.x;
         i < n; i += stride) {
        c[i] = a[i] + b[i];
    }
}

int main() {
    constexpr size_t n = 1u << 20;
    const size_t bytes = n * sizeof(float);
    std::vector<float> a(n, 1.0f), b(n, 2.0f), c(n);
    float *da = nullptr, *db = nullptr, *dc = nullptr;

    CUDA_CHECK(cudaMalloc(&da, bytes));
    CUDA_CHECK(cudaMalloc(&db, bytes));
    CUDA_CHECK(cudaMalloc(&dc, bytes));
    CUDA_CHECK(cudaMemcpy(da, a.data(), bytes, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(db, b.data(), bytes, cudaMemcpyHostToDevice));

    constexpr int threads = 256;
    const int blocks = int((n + threads - 1) / threads);
    vecadd<<<blocks, threads>>>(da, db, dc, n);
    CUDA_CHECK(cudaGetLastError());       // errori di lancio
    CUDA_CHECK(cudaDeviceSynchronize()); // errori di esecuzione

    CUDA_CHECK(cudaMemcpy(c.data(), dc, bytes, cudaMemcpyDeviceToHost));
    bool ok = true;
    for (float value : c) {
        if (!std::isfinite(value) || std::fabs(value - 3.0f) > 1e-6f) {
            ok = false;
            break;
        }
    }

    CUDA_CHECK(cudaFree(dc));
    CUDA_CHECK(cudaFree(db));
    CUDA_CHECK(cudaFree(da));
    std::puts(ok ? "OK" : "FAIL");
    return ok ? EXIT_SUCCESS : EXIT_FAILURE;
}
```

In codice di produzione usa RAII per liberare risorse anche in caso di errore. Per risultati generici floating point usa tolleranze assolute e relative.

## 4. Compilazione e strumenti

```text
nvcc --version
nvidia-smi
nvcc -O3 -std=c++17 -lineinfo vecadd.cu -o vecadd
nvcc -O3 -std=c++17 -arch=native vecadd.cu -o vecadd
nvcc -O3 -std=c++17 -Xptxas=-v vecadd.cu -o vecadd
```

`-arch=native` richiede GPU visibile e Toolkit che supporti l'opzione; per distribuire il binario configura esplicitamente le architetture con `-gencode`. Il build senza architettura esplicita usa il default del Toolkit.

Su Windows usa un terminale con compilatore host MSVC supportato configurato, output `vecadd.exe` ed esecuzione `.\vecadd.exe`; su Linux esegui `./vecadd`. `nvidia-smi` mostra la capacità CUDA del driver, non la versione del Toolkit installato. `-lineinfo` aiuta i profiler; `-G` serve per debug device e altera le prestazioni. `--use_fast_math` cambia proprietà numeriche: abilitalo solo dopo verifica.

Fonte: [NVCC](https://docs.nvidia.com/cuda/cuda-compiler-driver-nvcc/index.html).

## 5. Memoria: scelta rapida

| Memoria/API | Uso | Attenzione |
|---|---|---|
| Registri | Variabili private | Pressione elevata può causare spill |
| Local memory | Dati privati non tenuti nei registri | Risiede nella memoria device |
| Global / `cudaMalloc` | Buffer GPU | Allinea gli accessi e favorisci coalescing |
| Shared / `__shared__` | Scambio e riuso nel blocco | Sincronizzazione e bank conflict |
| Constant / `__constant__` | Dati in sola lettura sul device | Efficiente con letture uniformi nel warp |
| `cudaMallocManaged` | Puntatore condiviso CPU/GPU | Migrazioni e sincronizzazione restano rilevanti |
| `cudaMallocHost` | Buffer host pinned | Favorisce copie asincrone; libera con `cudaFreeHost` |

`cudaMemcpy(dst, src, bytes, cudaMemcpyHostToDevice)`, `cudaMemcpyDeviceToHost`, `cudaMemcpyDeviceToDevice`: dimensioni in **byte**. `cudaMemset` imposta byte: zero va bene per azzerare float, valore 1 non produce float 1.0.

Riduci i trasferimenti CPU↔GPU, mantieni i dati sul device, fai accedere lane consecutive a elementi consecutivi. Misura prima di usare shared memory o aumentare l'occupancy: più occupancy non implica automaticamente più velocità.

Fonte: [Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html).

## 6. Sincronizzazione e race

| Primitiva | Ambito / uso |
|---|---|
| `__syncthreads()` | Barriera e visibilità delle operazioni di memoria tra thread del blocco |
| `__syncwarp(mask)` | Sincronizzazione dei partecipanti nel warp |
| `atomicAdd(ptr, value)` | Aggiornamento atomico della posizione supportata |
| `cudaStreamSynchronize(s)` | L'host attende lo stream |
| `cudaDeviceSynchronize()` | L'host attende il lavoro precedente sul device corrente |

Tutti i thread partecipanti del blocco devono raggiungere la barriera: evita `if (i < n) __syncthreads();` quando la condizione varia nel blocco. Inizializza lo slot shared per ogni thread, poi sincronizza fuori dal ramo.

Non usare una barriera di blocco per coordinare blocchi diversi. Per fasi globali usa kernel separati ordinati nello stesso stream. Un'atomica non è una barriera; la somma floating point può variare con l'ordine degli aggiornamenti. Non assumere sincronizzazione implicita fra lane.

Fonte: [CUDA C++](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/intro-to-cuda-cpp.html), [Best Practices](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html).

## 7. Stream e copie asincrone

Stesso stream: operazioni ordinate. Stream diversi: concorrenza possibile, dipende da hardware, risorse e dipendenze. I frammenti seguenti usano `CUDA_CHECK` e `vecadd` dell'esempio; buffer e dimensioni devono essere già validi.

```cpp
cudaStream_t s;
CUDA_CHECK(cudaStreamCreateWithFlags(&s, cudaStreamNonBlocking));
// ha, hb, hc: buffer host pinned; da, db, dc: buffer device
CUDA_CHECK(cudaMemcpyAsync(da, ha, bytes, cudaMemcpyHostToDevice, s));
CUDA_CHECK(cudaMemcpyAsync(db, hb, bytes, cudaMemcpyHostToDevice, s));
vecadd<<<blocks, threads, 0, s>>>(da, db, dc, n);
CUDA_CHECK(cudaGetLastError());
CUDA_CHECK(cudaMemcpyAsync(hc, dc, bytes, cudaMemcpyDeviceToHost, s));
CUDA_CHECK(cudaStreamSynchronize(s)); // ora hc è leggibile
CUDA_CHECK(cudaStreamDestroy(s));
```

Mantieni vivi i buffer e non modificarli/riutilizzarli prima del completamento. Per sovrapporre copie host↔device e calcolo usa memoria pinned e verifica il supporto hardware. Non contare su copie da memoria pageable per un comportamento realmente asincrono. Per dipendenze tra stream: registra un evento nel produttore e usa `cudaStreamWaitEvent` nel consumatore. Il default stream può introdurre sincronizzazioni implicite.

Fonti: [Esecuzione asincrona](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html), [Stream API](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html).

## 8. Timing GPU con eventi

Frammento nello stream `s` già creato, con buffer inizializzati. Esegui un warm-up e attendine il completamento prima della misura.

```cpp
cudaEvent_t start, stop;
CUDA_CHECK(cudaEventCreate(&start));
CUDA_CHECK(cudaEventCreate(&stop));
CUDA_CHECK(cudaEventRecord(start, s));
vecadd<<<blocks, threads, 0, s>>>(da, db, dc, n);
CUDA_CHECK(cudaGetLastError());
CUDA_CHECK(cudaEventRecord(stop, s));
CUDA_CHECK(cudaEventSynchronize(stop));
float ms = 0.0f;
CUDA_CHECK(cudaEventElapsedTime(&ms, start, stop));
std::printf("%.3f ms\n", ms);
CUDA_CHECK(cudaEventDestroy(stop));
CUDA_CHECK(cudaEventDestroy(start));
```

Ripeti la misura e specifica se includi trasferimenti. Un timer CPU attorno al solo lancio misura soprattutto l'invio; per il tempo completo serve attendere la GPU. Altre attività GPU possono influenzare il tempo misurato.

Fonte: [Event API](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__EVENT.html).

## 9. Debug e diagnosi

```text
compute-sanitizer --tool memcheck ./vecadd
compute-sanitizer --tool racecheck ./vecadd
compute-sanitizer --tool initcheck ./vecadd
compute-sanitizer --tool synccheck ./vecadd
```

Su Windows sostituisci `./vecadd` con `.\vecadd.exe`.

| Sintomo | Primo controllo |
|---|---|
| Illegal memory access | Bound, byte allocati, puntatori, durata buffer; memcheck |
| Risultati intermittenti | Race, barriera divergente, buffer riusati troppo presto |
| Valori mai scritti | Inizializzazione memoria globale; initcheck |
| Barriere errate | synccheck |
| Kernel lento | Accessi non contigui, divergenza, spill, trasferimenti |

Racecheck analizza hazard della **shared memory**: non prova l'assenza di ogni race globale. Controlla errori subito dopo il lancio e a un punto di sincronizzazione; un errore asincrono può emergere in una chiamata successiva.

Fonte: [Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html).

## 10. Promemoria operativo

1. Verifica il risultato rispetto a una versione CPU, anche con dimensioni non multiple del blocco.
2. Elimina accessi fuori limite e race.
3. Misura kernel e trasferimenti separatamente.
4. Ottimizza il collo di bottiglia misurato.
5. Per operazioni standard valuta librerie NVIDIA come cuBLAS, cuFFT e CUB prima di scrivere kernel complessi.
