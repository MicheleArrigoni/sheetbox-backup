# Submission del job CUDA `ex2.sh` con Slurm

Comandi da eseguire nel terminale Linux del cluster. Questa scheda documenta la procedura: non invia alcun job.

## 1. Cartella e ambiente CUDA

```bash
cd /csghome/gpu15/assignmen2/template

source /opt/csg/spack/share/spack/setup-env.sh
spack env activate cuda
spack find cuda
```

Carica una versione elencata dal comando precedente, sostituendo `VERSIONE`:

```bash
spack load cuda@VERSIONE
which nvcc
```

Il testo fornito indica di compilare sul nodo di accesso e di eseguire il programma sui nodi di calcolo tramite Slurm.

## 2. Correggi CRLF e compila

```bash
sed -i 's/\r$//' ex2.sh
file ex2.sh
chmod +x ex2.sh
bash -n ex2.sh

mkdir -p bin
make
ls -l bin/nullKernelAsync
```

- `sed` elimina il carattere CR alla fine di ogni riga. `file` non dovrebbe più segnalare terminatori CRLF.
- `bash -n` controlla la sintassi della shell, senza eseguire lo script; non valida le risorse Slurm.
- `chmod +x` abilita l'esecuzione diretta; `sbatch ex2.sh` richiede che il file sia leggibile e non necessita del bit eseguibile.
- Il Makefile locale produce `bin/nullKernelAsync`; crea prima la cartella `bin`.
- Se necessario, converti anche il Makefile: `sed -i 's/\r$//' Makefile`.

## 3. Controlla le richieste Slurm

Il template locale contiene:

```bash
#!/usr/bin/env bash
#SBATCH --gres=gpu:1
#SBATCH -p exercise
#SBATCH -o ex2_out.txt

bin/nullKernelAsync
```

**Partizione da verificare:** il template usa `exercise`; il testo incollato attribuisce alla guida la partizione `exercise-gpu`. Usa quella indicata per la tua esercitazione. Per vedere le partizioni:

```bash
sinfo
```

Il testo fornito indica che il limite `--time` è obbligatorio. Lo script locale non lo contiene: aggiungi, prima del comando del programma:

```bash
#SBATCH --time=00:30:00
```

I 30 minuti sono un esempio da adattare ai limiti del corso. Eventuali richieste `--cpus-per-task=2` e `--mem=16G` sono quelle dell'esempio riportato nel testo fornito; adattale alle necessità e alle regole del cluster.

## 4. Invia il job

Dopo aver impostato partizione e tempo nello script:

```bash
sbatch ex2.sh
```

In alternativa, puoi fornire il tempo al comando senza modificare lo script:

```bash
sbatch --time=00:30:00 ex2.sh
```

Se la partizione confermata è `exercise-gpu`, puoi sovrascrivere quella del template per questo invio:

```bash
sbatch --partition=exercise-gpu --time=00:30:00 ex2.sh
```

**Esegui una sola delle alternative:** ogni chiamata a `sbatch` invia un nuovo job.

Risposta attesa:

```text
Submitted batch job 123456
```

Conserva l'ID restituito. La conferma indica che il job è stato accettato, non che sia già terminato.

## 5. Stato, output e annullamento

Sostituisci `123456` con l'ID reale:

| Operazione | Comando |
| --- | --- |
| Elenca i tuoi job | `squeue -u "$USER"` |
| Controlla un job | `squeue -j 123456` |
| Previsione di avvio, se disponibile | `squeue --start -j 123456` |
| Segui l'output | `tail -f ex2_out.txt` |
| Leggi l'output | `cat ex2_out.txt` |
| Annulla il job | `scancel 123456` |
| Efficienza a fine job, se disponibile | `reportseff 123456` |

`PD` = in attesa; `R` = in esecuzione. In caso di attesa, leggi il motivo mostrato da `squeue`.

Il file di output può comparire solo quando il job parte. `Ctrl-C` interrompe `tail`, lasciando proseguire il job. Se il job scompare da `squeue`, controlla l'esito: questo da solo non dimostra il successo.

Se il cluster dispone della contabilità Slurm:

```bash
sacct -j 123456 --format=JobID,JobName,State,ExitCode,Elapsed
```

Per distinguere gli output di invii successivi, puoi usare nello script `#SBATCH --output=ex2_%j.out`; in quel caso leggi il file corrispondente all'ID del job.

## Problemi frequenti

- **Errore sui terminatori DOS/CRLF:** ripeti `sed -i 's/\r$//' ex2.sh` sulla copia presente nel cluster.
- **Partizione non valida:** controlla `sinfo` e le istruzioni dell'esercitazione.
- **Limite di tempo mancante:** imposta `#SBATCH --time=...` o passa `--time=...` a `sbatch`.
- **`nvcc` non trovato:** inizializza Spack e carica CUDA prima di compilare.
- **Eseguibile assente:** esegui `mkdir -p bin` e `make`, verificando che la compilazione riesca.
- **Librerie CUDA mancanti nel job:** prepara l'ambiente CUDA anche nello script, dopo le direttive `#SBATCH` e prima del programma, secondo la configurazione del cluster.

In VS Code scegli **LF** nella barra di stato prima di salvare `ex2.sh`.
